# Production-readiness audit, November 2026

An outside-style review of commit `7f3e25e`, done by three reviewers working separately (on-call
engineer, maintainer, security), against the question "could this run in a clinic tomorrow?"

**Verdict: not production-ready. The reasons can be fixed in weeks, not months.** The pipeline,
the policy layer (OPA with tested Rego), the profile loader and the approval path were rated
sound and should not be rewritten. What is missing is the usual gap between a working system on
one machine and a service in an organization: verified identity, a secured message bus, and
supervision.

- 7 blockers, 21 majors, 23 minors (+3 nits)
- Estimated effort for all blockers and majors: about 160 hours
- Fixed since the audit (as of November 8): all 7 blockers in full or in part, and 13 of 21 majors in
  full or in part (marked below). SC-3 (Kafka TLS, sign-in and ACLs) was fixed last, with the cloud
  deployments it depends on (ADR 031)

## Blockers

| ID | What | Fix |
|----|------|-----|
| SC-1 | The role is a field in the request; policy, data-class filtering and role checks trust it | **Fixed with sign-in on (ADR 028):** the role comes from the person's groups in a verified OIDC token (Keycloak, Entra ID, Okta ...). Demo mode keeps the request's role, for one machine only. Open: SMART on FHIR (Epic) and the governed endpoint's own OIDC option |
| SC-2 | The approver's identity comes from the request; the two-person rule compares caller-chosen strings | **Fixed with sign-in on (ADR 028):** the approver and their role come from their token, so the two-person rule compares two signed-in people |
| SC-3 | Unmasked text travels on a Kafka bus with no TLS or authentication | **Fixed (ADR 031):** every client connects through `ops/kafka.py` (TLS, SCRAM per service, Entra ID or MSK IAM; plaintext to another machine refused); one access list (`ops/kafka_access.yaml`) becomes the local ACLs, the MSK IAM policies and the Event Hubs roles; a secured local broker (`GOVERNED_KAFKA_SECURE=on`); private-only Terraform for Azure and AWS. Open: GCP |
| SC-4 | `/events` and `GET /chat/{id}` have no authentication | **Fixed with sign-in on (ADR 028):** both need a valid token; an answer is readable only by the person who asked; the profile can limit the dashboard to named roles |
| OC-1 | One request at a time; a long hang could evict the planner from Kafka | **Partly fixed:** poll interval raised to 15 min, commit guarded, every tool call now has a timeout (OC-6). Open: per-request deadline, several workers |
| OC-2 | No Kafka delivery callbacks; a lost message is not noticed | **Fixed (ADR 030):** every message has a delivery callback; failures are counted, logged and shown by `/health`; a lost audit event is reported as a gap; a chat message or approval the broker did not confirm gets 503 "try again" |
| OC-3 | No restart on crash; `/health` does not check the workers | **Fixed (ADR 030):** every service runs under a supervisor (restart with backoff, gives up visibly after 5 crashes in 2 minutes); `/health` checks the broker, the API's reader threads, the planner and executor heartbeats and delivery: ok, degraded or down (503) |

## Second review (November 5, 2026)

Three reviewers looked again at commit `697f4b0`, independently and without this document: 5
blockers, 17 majors, 29 minors, about 157 hours for blockers and majors. They confirmed the fixes
above, found the November blockers still open, and found new issues. Fixed since then:

| Finding | What | Fix |
|---|---|---|
| Blocker | An approval decided while the executor was down was never carried out | On start the executor finishes approved changes that have no result (safe to repeat: one change per approval ID); an error inside a decision is recorded as a failed result instead of stopping it; the executor runs from `main()` and has tests (`tests/test_executor.py`) |
| Blocker (part) | The audit log was kept for Kafka's default 7 days | Audit and approval topics are kept for good (`retention.ms=-1`, `scripts/dev.sh`); an archive with signed checkpoints is still open |
| Blocker (part) | Kafka, OPA and Kafka UI were published on every network interface | Published on 127.0.0.1 only (`docker-compose.yml`); authentication on Kafka and OPA is still open, for a deployment beyond one machine |
| Major | One malformed approval event stopped the executor's start, or silently ended an API reader thread | Malformed events are skipped and reported |
| Major | Web research followed redirects without checking them | Redirects followed by hand, every hop checked against https, the allow-list and local addresses; pages recorded under the URL actually read |
| Major (part) | A misspelled or empty `allow:` in `web_research.yaml` allowed every site | Unknown keys and an empty allow-list are refused when the server starts |
| Major | Tests of the record and gateway servers were skipped, not failed, when an import broke | Plain imports |
| Major (part) | No size limit on a chat message | 4,000 characters, as for history turns |

Fixed since (November 8, ADR 030): signed audit checkpoints (a deleted tail, a rewritten
checkpointed event or a deleted chain is found), Kafka delivery callbacks, health checks and
supervision, a rate limit per person, OPA token authentication and mutual TLS to the tool servers.

Fixed since (November 8, ADR 031): Kafka TLS, a sign-in per service and least-privilege access
(SC-3), locally and in private deployments on Azure and AWS.

Still open from the second review: request deadlines, the outside endpoint's own copy
of the answer path, and the duplicated input checks.

## What this means for a pilot

The system is suitable for demonstrations and evaluation with synthetic data, which is how it is
used today. Before real patient, client or student data, an organization needs: identity from its
own sign-in system (SC-1, SC-2, SC-4, SC-11), the message bus and policy engine closed to the
network (SC-3, SC-5, SC-6), and supervision (OC-1, OC-2, OC-3). These are deployment choices that
depend on the organization's identity provider and hosting, which is why they are left open in
the reference architecture rather than guessed.
